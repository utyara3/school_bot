# 🏫 School Bot

Многофункциональный Telegram-бот для автоматизации школьной жизни: расписание уроков, система поддержки, управление пользователями и ролями.

> ⚠️ **Статус проекта:** В настоящее время разработка приостановлена.

## ✨ Возможности

### 📅 Расписание уроков
- База данных с предметами, классами (5А–11Е) и днями недели
- Просмотр расписания для любого класса на любую неделю
- Автоматическая инициализация стандартных школьных предметов

### 🎫 Система поддержки (тикет-система)
- Пользователи могут отправлять сообщения в поддержку через `/support`
- Тикеты проходят через статусы: `pending` → `in_progress` → `resolved`
- Саппорты получают уведомления о новых обращениях
- История всех тикетов сохраняется в БД

### 👥 Ролевая система (RBAC)
Четыре уровня доступа с разными привилегиями:

| Роль | Уровень | Описание |
|------|---------|----------|
| `student` | 1 | Базовый доступ к функционалу |
| `support` | 10 | Доступ к тикетам поддержки |
| `supervisor` | 100 | Глобальные оповещения |
| `admin` | 1000 | Полный доступ к управлению ботом |

### 🛡️ Анти-спам система
Двухуровневая защита от спама через middleware:
- **Предупреждение** — при превышении порога сообщений в секунду
- **Игнорирование** — при превышении критического порога
- Автоматическая очистка неактивных пользователей из памяти

### 🔐 Админ-панель
- Управление ролями пользователей (добавление/удаление)
- Просмотр списка пользователей с пагинацией
- Логирование всех административных действий

### 📊 Профили пользователей
- Команда `/profile` показывает информацию о пользователе
- Автоматическая регистрация новых пользователей при `/start`

## 🛠️ Технологии

| Библиотека | Назначение |
|------------|-----------|
| `aiogram 3.x` | Асинхронный фреймворк для Telegram Bot API |
| `aiosqlite` | Асинхронная работа с SQLite |
| `python-dotenv` | Управление конфигурацией через `.env` |

### Архитектурные особенности
- **FSM (Finite State Machine)** — многошаговые диалоги через состояния
- **Middleware** — перехват и обработка событий до хендлеров
- **Custom Filters** — кастомные фильтры для проверки ролей (`AccessFilter`)
- **Модульная структура** — разделение на handlers, database, keyboards, filters, middlewares, utils
- **Асинхронность** — все операции с БД и API асинхронные

## 🚀 Установка и запуск

### Требования
- Python 3.10+
- Telegram Bot Token (получить у [@BotFather](https://t.me/BotFather))

### Шаги установки

```bash
# Клонируем репозиторий
git clone https://github.com/utyara3/school_bot.git
cd school_bot

# Создаём виртуальное окружение
python -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate     # Windows

# Устанавливаем зависимости
pip install -r requirements.txt

# Копируем пример конфигурации
cp .env-example .env
```

### Конфигурация `.env`

```env
# Токен бота от @BotFather
BOT_TOKEN=your_bot_token_here

# ID администраторов через запятую
GENERAL_ADMINS=123456789,987654321

# Путь к базе данных SQLite
DATABASE_PATH=database.db

# Имя логгера
LOGGER_NAME=school_bot

# Пороги анти-спама (сообщений в секунду)
ANTI_SPAM_MESSAGES_PER_SECOND=2
ANTI_SPAM_MESSAGES_PER_IGNORE=4
```

### Запуск

```bash
python main.py
```

При первом запуске автоматически:
- Создаётся база данных SQLite
- Инициализируются все таблицы (users, roles, schedule, support_tickets)
- Заполняются стандартные данные (дни недели, предметы, классы, роли)
- Добавляются администраторы из `GENERAL_ADMINS` в БД

## 🎮 Использование

### Команды для всех пользователей

| Команда | Описание |
|---------|----------|
| `/start` | Регистрация и приветственное сообщение |
| `/cancel` | Отмена текущего действия |
| `/support` | Отправить сообщение в поддержку |
| `/profile` | Показать информацию о пользователе |

### Команды для администраторов

| Команда | Описание |
|---------|----------|
| `/admin_panel` | Открыть панель администратора |

### Админ-панель

После ввода `/admin_panel` доступны опции:
- **Добавить роль** — выдать пользователю новую роль по ID
- **Убрать роль** — отозвать роль у пользователя
- **Пользователи** — просмотр списка пользователей с пагинацией

### Система поддержки

1. Пользователь отправляет `/support` или пишет "поддержка"
2. Бот переходит в режим ожидания сообщения
3. Сообщение пользователя создаёт тикет и рассылается всем саппортам
4. Саппорт нажимает "Ответить" и вводит ответ
5. Ответ отправляется пользователю, тикет помечается как `resolved`

## 🗃️ Схема базы данных

```sql
-- Пользователи и роли
users (id, tg_id, username, first_name, last_name, created_at)
roles (id, name, description, permission_level)
user_roles (user_id, role_id) -- many-to-many

-- Расписание
subjects (id, name, short_name)
weekdays (id, name, short_name, order_index)
classes (id, name)
schedule_entries (id, weekday_id, class_id, subject_id, lesson_number)

-- Поддержка
support_tickets (id, user_id, support_id, message_text, status, answer_text, created_at)
```
